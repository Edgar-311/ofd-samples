# ofd-samples

公开的 OFD 测试文件集，任何语言的 OFD 库都可以拿来做测试。每个文件都附带期望输出。
An open set of OFD test files (GB/T 33190) for testing OFD libraries in any language. Each file comes with its expected output.

目前有 22 个样本，包括阅读顺序（分栏、竖排标签）、多页、模板、复合对象、坐标变换、自定义标签、附件，以及实际文件里常见的不规范写法（路径大小写不一致、GBK 文件名、GB18030 编码、错误的 XML 前缀等）。完整列表见 [CATALOG.md](CATALOG.md)。
There are 22 samples covering reading order (columns, vertical labels), multiple pages, templates, composite objects, transforms, custom tags and attachments, plus non-conforming files of the kinds found in the wild (wrongly cased paths, GBK entry names, GB18030 XML, broken XML prefixes). See [CATALOG.md](CATALOG.md).

## 原则 / Principles

- 所有文件都是普通的测试文档：不做任何看起来像发票的文件，不包含真实的个人或企业信息。
  All files are plain test documents: nothing that looks like an invoice, and no real personal or company data.
- 所有文件都由 [generator/build_samples.py](generator/build_samples.py) 生成，可以审查、可以重新生成，不是来历不明的二进制文件。
  Every file is generated by [generator/build_samples.py](generator/build_samples.py), so it can be reviewed and rebuilt rather than trusted as an opaque binary.
- 期望的坐标是按标准的坐标规则从生成脚本描述的内容直接算出来的，不是任何 OFD 阅读器的输出。
  Expected coordinates are computed from what the generator describes, using the standard's coordinate rules, not taken from any OFD reader.
- 本项目大部分内容由 AI（Claude）生成，维护者负责决定方向和批准发布。
  Most content is generated with AI assistance (Claude). The maintainer sets the direction and approves releases.

## 文件结构 / Layout

```
samples/<name>.ofd      测试文件 / the test files
expected/<name>.json    期望输出 / expected output
generator/              生成脚本 / the generator (Python standard library only)
CATALOG.md              样本列表 / list of samples
```

## 期望输出的格式 / Expected output format

```json
{
  "name": "text-transforms",
  "conforming": true,
  "features": ["CTM", "TextCode X/Y reuse", "DeltaX shorthand"],
  "doc_info": {"title": "测试样例", "custom_data": {}},
  "pages": [
    {
      "id": "1",
      "width": 210.0,
      "height": 297.0,
      "readable": true,
      "text": "缩放两倍\n前半 后半\n间距相等的文字",
      "text_objects": [
        {"id": "101", "text": "缩放两倍", "size": 4.0, "from_template": false,
         "runs": [{"text": "缩放两倍", "x": 22.0, "y": 24.0}]}
      ]
    }
  ],
  "custom_tag_values": [{"path": "InvoiceNo", "value": "00000001"}]
}
```

- `conforming`：文件是否符合标准。`false` 的样本测试的是容错能力。
  Whether the file follows the standard. Non-conforming samples test tolerance.
- `width`、`height`：页面尺寸，单位毫米。`readable` 为 `false` 表示这一页的内容文件缺失。
  Page size in millimetres. `readable: false` means the page's content file is missing.
- `text`：这一页按阅读顺序的文字，一行一行。比较时请忽略空行，并把连续的空白当作一个空格。
  The page's text in reading order, line by line. Compare ignoring blank lines and treating any run of whitespace as one space.
- `text_objects`：页面上的每个文字对象（包括来自模板的，`from_template` 为 `true`）。`runs` 是每个 TextCode 第一个字的基线位置，单位毫米，原点在页面左上角，已经计算了 Boundary、CTM 和复合对象的变换。`size` 是变换后的字号。
  Every text object on the page, including template objects (`from_template: true`). `runs` gives the baseline position of each TextCode's first glyph in millimetres from the page's top-left corner, after Boundary, CTM and composite-object transforms. `size` is the font size after transforms.
- `custom_tag_values`、`attachment_values`：自定义标签和附件里的值，按文档顺序。通过 ObjectRef 引用多个文字对象时，值是这些对象文字的拼接。
  Values in custom tags and attachments, in document order. A field that references several text objects by ObjectRef has their texts joined.

坐标请用 0.001 毫米的误差比较。Compare coordinates with a tolerance of 0.001 mm.

## 重新生成 / Regenerating

```bash
python generator/build_samples.py          # 重新生成 / rebuild
python generator/build_samples.py --check  # 检查已提交的文件是否最新 / verify the committed files
```

## 谁在用 / Used by

Other OFD projects are welcome to use them. To ask for a sample of some structure, open an issue describing the structure; please do not upload real files.
